# Multipanels demo on real Kibana

A real Kibana (this checkout, upstream `main`) running in **serverless Security** mode, cut down so
that only three areas are reachable:

| Live page | Route | Data |
| --- | --- | --- |
| **AlertZero** (+ Escalations, Watches) | `/app/alertzero` | 3 seeded proposals + their Agent Builder conversations |
| **Alerts** (inside the *Detections* group) | `/app/security/alerts` | ~140 detection alerts generated by Kibana's own data generator |
| **Agents** (Agent Builder) | `/app/agent_builder` | Chat against a canned, OpenAI-compatible mock LLM |

Every other Security side-navigation item keeps its icon and label but is **disabled**: it does not
navigate, does not open its hover panel and is skipped by keyboard navigation. Login is
`elastic` / `changeme`; the default route is the Alerts page.

## Run it

```bash
multipanels_kibana/setup.sh all
```

That installs Node (`.nvmrc`) + pnpm, runs `kbn bootstrap`, starts Elasticsearch, the mock LLM and
Kibana in three tmux sessions (`multipanels-es`, `multipanels-mock-llm`, `multipanels-kibana`), waits
for Kibana and seeds the data. Each step is also available on its own
(`setup.sh deps|es|mock-llm|kibana|seed`) if you prefer your own terminals. Kibana takes a few minutes
on first start while the dev bundler compiles.

Requirements: ~16 GB RAM free (ES 2 GB heap + Kibana + dev optimizer), Node from `.nvmrc`, no Docker.

## What is in here

- `kibana.multipanels.yml` – the only Kibana config the demo needs. It is loaded with `--config`
  *on top of* `config/serverless.yml` + `config/serverless.security.yml` (the dev CLI splices those
  in for `--serverless=security`), so it only holds the deltas: ES connection + basic auth, the
  AlertZero / Agent Builder feature switches, the navigation allowlist, the preconfigured mock LLM
  connector and a handful of plugins turned off.
- `mock_llm_server.mjs` – canned OpenAI chat-completions server (streaming and non-streaming).
  Structured-output requests (`tool_choice`) get a tool call with arguments filled from the JSON
  schema (that is how conversation titles get generated); everything else gets a markdown security
  analysis chosen by keywords in the prompt.
- `setup.sh` – the end-to-end script described above.

## How the navigation is cut down

`xpack.securitySolutionServerless.navigationAllowlist` (new, browser-exposed config of the
`securitySolutionServerless` plugin) lists the deep-link ids that stay clickable:

```yaml
xpack.securitySolutionServerless.navigationAllowlist:
  - 'securitySolutionUI:alerts'
  - 'alertzero'
  - 'alertzero:escalations'
  - 'alertzero:watches'
  - 'agent_builder'
```

`public/navigation/demo_navigation_restrictions.ts` walks the Security navigation tree and sets
`isDisabled: true` on every node that is not allow-listed (a group stays enabled while one of its
children is allowed, which is how the *Detections* group still leads to Alerts). Nodes keep their
`link`, so core does not prune them and they still render.

`isDisabled` is a new, optional flag on the chrome `NodeDefinition` that flows through
`toNavigationItems` into `@kbn/ui-side-navigation`, where a disabled item renders as a
`<button disabled>` with muted colors instead of a link, never opens its popover / side panel, and
panel openers pick their landing href from the first *enabled* child. Nothing changes for trees that
do not set the flag (unit tests cover both).

## Fake data

- **Alerts** – `x-pack/solutions/security/plugins/security_solution/scripts/data/generate_cli.js`
  (Kibana's Security data generator) replays vendored attack episodes as endpoint events and
  Okta / AWS IAM / Kubernetes / GitHub audit events, then mints *honest* detection alerts through
  Rule Preview (every alert comes from a rule whose query matched). Plus the 8 hand-labelled
  Elastic Defend alerts from `alertzero/scripts/index_eval_alerts.js`, which supply the critical,
  high and low severities (the generator's rules are all medium).
- **AlertZero** – `alertzero/scripts/seed_proposal_attachments.sh` writes 3 proposals (2 pending,
  1 dismissed) into `.kibana-proposals` and creates the matching Agent Builder conversations.
- **Agents** – nothing to seed; the preconfigured `Demo LLM (canned responses)` connector is
  selected by default and answers from the mock server.

## What is disabled and why

Besides the navigation allowlist, `kibana.multipanels.yml` turns off plugins that only add startup
and page-load cost and contribute nothing to the three live pages: Automatic Import, content
connectors, Streams, Agent Builder workflows, indices metadata, OTel collection, product intercept,
telemetry, newsfeed and the Fleet package install on boot. `config/serverless.yml` already disables
canvas, monitoring, ILM, rollups, snapshot/restore, upgrade assistant, graph, watcher, … Plugins that
own side-nav items are left on so their items can render disabled.

## Caveats (read before demoing)

- **Stateful Elasticsearch in serverless Kibana mode.** There is no Docker here, so Kibana runs with
  `--serverless=security --no-uiam` against `node scripts/es snapshot` (trial license). Two dev-only
  accommodations make that work: the `elastic/kibana/kibana-dev` service-account token is installed
  into the ES config dir, and the security plugin only *warns* instead of failing when
  `xpack.security.uiam.enabled` is false **in development mode** (production serverless still
  throws). Basic auth replaces the mock IdP / SAML login.
- **AlertZero is display-only.** Proposals come from the seed script, so Approve / Decline return
  409 (no gate workflow execution behind them). Workers, Watches and real investigations need the
  UIAM-backed service accounts and a real LLM; neither exists here. The server logs one
  `Service accounts are enabled but the UIAM service was never constructed` error at boot for the
  same reason (the UI gate only looks at the config flag).
- **The mock LLM does not understand anything.** It is enough for Agent Builder chat, titles and the
  alert flyout's AI summary button to produce plausible output; anything that must *act* on the
  answer (tool selection, ES|QL generation, Attack Discovery, AlertZero triage) needs a real
  connector. Point `xpack.actions.preconfigured.multipanels-mock-llm` at one to upgrade.
- Pages that are disabled in the nav are still reachable by URL; nothing is removed from Kibana.
- `uiSettings.overrides` pins the chat experience to Agent Builder and AlertZero on; those settings
  are read-only in Advanced Settings while the override is in place.
